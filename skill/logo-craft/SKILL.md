# 로고 제작

## 이 스킬이 존재하는 이유

로고는 웹 UI와 다르다. **납품물이 벡터 파일과 사용 규칙**이고, 인쇄·자수·간판·파비콘까지 살아남아야 한다. 예쁜 그림을 만드는 작업이 아니라, **제약을 통과하는 형태를 만드는 작업**이다.

## 절대 규칙 — AI 경계선

**로고의 최종 형태를 이미지 생성 AI로 만들지 않는다.** 요청받아도 하지 않는다.

이유는 취향이 아니라 기능이다. 로고 납품물은 벡터(SVG/AI) + 사용 가이드다. 생성 AI 출력은 래스터라 ①확대하면 깨지고 ②인쇄소가 못 받고 ③선 굵기를 못 고치고 ④자수·각인 데이터로 못 넘긴다. 래스터를 벡터로 자동 변환해도 앵커가 수백 개 생겨 수정 불가능한 형태가 된다.

| AI가 하는 것 | 사람이 하는 것 |
|---|---|
| 컨셉 발산, 연상 확장, 네이밍 후보 | 형태 결정과 드로잉 (피그마/일러스트) |
| 경쟁사 조사 정리, 팔레트·폰트 후보 | 곡선 보정, 광학 정렬, 자간 |
| 무드보드 이미지, 목업 배경 | 최종 판단 |
| 브랜드 가이드 조판, 검증 시트 생성 | 설명 논리 |

"로고 그려줘"를 받으면: 왜 안 되는지 두 줄로 말하고, **대신 무엇을 해줄지** 제시한다 — 방향 3안 + 각 안의 형태 설명 + 참고 좌표. 그리는 건 사람 몫으로 남긴다.

## 작업 순서

리서치 → 발산 → 정제 → **검증** → 적용 → 가이드

건너뛰지 않는다. 특히 **발산 없이 정제로 가지 않는다.** 첫 아이디어가 좋아 보이는 건 다른 걸 안 봐서다.

| 단계 | 산출물 | 게이트 |
|---|---|---|
| 리서치 | 경쟁사 12곳 실루엣 비교, 무드보드, 브리프 확정 | 클리셰 목록이 나왔나 |
| 발산 | 스케치 30안 (서로 다른 30개, 변주는 1개로 셈) | 30개 미만이면 진행 금지 |
| 정제 | 3~5안 벡터화 + 각 안의 "형태의 이유" 한 문장 | 이유를 못 쓰는 안은 탈락 |
| 검증 | 검증 시트 (아래 6개) | 6개 전부 통과해야 다음 |
| 적용 | 목업 — 실제로 붙는 자리에 | 예쁜 목업으로 이기려 들지 않는다 |
| 가이드 | 변형 세트 + 브랜드 가이드 + 파일 포맷 세트 | `references/deliverables.md` 체크리스트 |

## 검증 6 — 통과 못 하면 형태를 고친다

1. **16px 식별** — 파비콘 크기에서 뭔지 알아본다
2. **1색 성립** — 흑백 단색으로 형태가 죽지 않는다
3. **반전 성립** — 어두운 배경 흰 로고로 성립한다
4. **실루엣 차별** — 경쟁사 3곳과 나란히 놓으면 안 겹친다
5. **설명 가능** — 형태의 이유를 한 문장으로 말한다
6. **30안 발산** — 버린 시안이 30개 이상 남아 있다

**칸이 안 맞으면 형태를 고치지 칸을 고치지 않는다.** 기준을 낮추는 순간 이 절차 전체가 장식이 된다.

### 검증 6은 최소 조건이지 충분 조건이 아니다

여섯 칸을 다 통과하고도 **엉뚱한 것으로 읽히는** 형태가 나온다. 실측 사례가 있다 — 기준을 전부 넘긴 심볼이 목업에서 새 옆모습으로 읽혔다. 기계는 16px에서 뭉개지는지는 재지만 **무엇으로 읽히는지는 못 잰다.**

그래서 정제 단계마다 **블라인드 읽힘 테스트**를 돌린다. 만든 사람은 자기 로고가 뭐로 보이는지 판정할 수 없다.

```bash
node ~/.claude/skills/logo-craft/assets/blind-stimulus.mjs <파일.svg>
```

브랜드 단서를 제거한 자극 3장을 만든다. 절차와 판정 기준은 `references/blind-read.md`. **설명이 필요한 형태는 실패한 형태다.**

SVG가 있으면 검증을 자동화한다:

```bash
node ~/.claude/skills/logo-craft/assets/verify-logo.mjs <파일.svg> --name "브랜드명"
```

크기별 렌더·1색·반전·크라프트 배경·원형 크롭·여백 시트를 한 장으로 뽑고, 래스터 삽입·미아웃라인 텍스트·그라데이션·과다 앵커를 기계적으로 잡아낸다.

## 언제 무엇을 읽나

| 상황 | 읽을 것 |
|---|---|
| **형태가 무엇으로 읽히는지 재야 할 때** | `references/blind-read.md` — 정제 단계마다 돌린다 |
| 시안을 비평할 때 | `references/critique.md` — **고정 출력 형식이 있다. 그대로 따른다** |
| 납품물·파일 포맷·공법 제약을 다룰 때 | `references/deliverables.md` |
| 사용자가 무엇을 어떻게 요청해야 할지 모를 때 | `references/prompt-cards.md` |
| 새 케이스의 피그마 작업 파일을 세팅할 때 | `assets/figma-case-setup.md` |

## 비평은 칭찬하지 않는다

시안을 보여주면 좋은 점부터 말하고 싶어진다. 그러면 실력이 안 는다. `references/critique.md`의 고정 형식을 쓴다 — 판정 한 줄 → 검증 6 체크 → 형태 지적(심각한 순) → 고치는 법 → 다음에 할 것 하나. 칭찬은 마지막 한 줄.

시안이 3개 이상이면 **반드시 순위를 매긴다.** "다 좋다"는 답이 아니다.

모든 지적은 검증 가능해야 한다. "촌스럽다"는 지적이 아니다. "16px에서 속공간이 막힌다"가 지적이다.

## 흔한 실패

| 증상 | 실제 원인 | 대응 |
|---|---|---|
| 시안이 다 비슷하다 | 발산 없이 첫 아이디어를 변주했다 | 30안으로 돌아간다. 변주는 1개로 센다 |
| 축소하면 뭉갠다 | 요소가 3개 이상이거나 획이 굵다 | 요소를 줄이거나 축소 전용 단순화판을 따로 만든다 |
| 흑백에서 사라진다 | 색·그라데이션이 형태를 만들고 있다 | 형태만으로 성립하게 다시 그린다 |
| 경쟁사와 겹친다 | 1차 연상물을 그대로 썼다 (빵집=밀, 카페=원두) | 연상을 한 단계 비튼다 |
| 워드마크가 밋밋하다 | 기성 폰트를 타이핑만 했다 | 최소 2군데 손본다 — 획끝·연결·자간·받침 |
| 목업은 좋은데 로고가 약하다 | 목업으로 이기려 했다 | 흰 배경 단독으로 다시 본다 |

## 하지 않는 것

- 생성 AI로 최종 로고 형태 만들기 (요청받아도)
- 검증 6을 통과 못 한 안을 적용 단계로 넘기기
- 시안 순위 없이 "다 좋다"고 답하기
- 상표 등록 가능성 판단 — 변리사 영역이다. 유사 상표가 걱정되면 키프리스 검색을 권하되 판단은 하지 않는다
- 실존 브랜드 로고를 참고를 넘어 복제하기
