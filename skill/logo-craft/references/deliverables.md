# 로고 납품물 레퍼런스

로고를 넘길 때 무엇을, 어떤 규격으로 주는지의 실무 체크리스트. 수치는 실무 통용 범위이며, 실제 제작 전에는 반드시 해당 업체(인쇄소·자수집·간판집)에 확인한다.

---

## 1. 기본 납품 세트 (티어별 구성)

가격 숫자는 시장에 따라 널뛴다. 기준은 "무엇이 들어가느냐"다. 한국 크몽류 마켓은 초저가와 고가로 양극화되어 있고, 저가 티어는 **원본 소스파일 미제공 + 수정 1~2회**로 단가를 맞추는 구조다.

| 항목 | 저가 | 중가 | 고가 |
|---|---|---|---|
| 시안 개수 | 1~2안 | 2~3안 | 3안 + 방향 리서치 |
| 로고 변형 | 조합형 1종 | 가로/세로 + 심볼 단독 | 전체 세트(§3) |
| PNG(투명) | O | O, 다중 해상도 | O, 다중 해상도 |
| JPG | O | O | O |
| 벡터 원본(AI/EPS) | X 또는 유료 옵션 | O | O |
| SVG | 드물게 | O | O |
| PDF(인쇄용) | X | O | O |
| CMYK 버전 | X | O | O |
| 별색(팬톤) 지정 | X | 선택 | O |
| 흑백/반전 버전 | X | O | O |
| 브랜드 가이드 | X | 1~2p 요약 | 10p+ 정식 가이드 |
| 폰트 아웃라인화 | 필수(티어 무관) | 필수 | 필수 |
| 명함/썸네일 목업 | X | 1~2종 | 적용 예시 다수 |
| 디지털 규격 세트 | X | 파비콘 정도 | §6 전체 |
| 수정 횟수 | 1~2회 | 3회 | 협의(단계별) |
| 저작권 처리 | 사용허락 | 양도 협의 | 양도 명시 |

**티어 구분의 실질**: 저가는 "이미지 파일", 중가는 "벡터 + 상황별 변형", 고가는 "브랜드가 스스로 운용 가능한 규칙"을 판다. 소스파일과 가이드가 있으면 클라이언트가 다음 디자이너 없이도 굴러가고, 그게 가격 차이의 근거다.

## 2. 파일 포맷 — 뭘 주고 왜 주나

| 포맷 | 성격 | 주 용도 | 주의 |
|---|---|---|---|
| **AI** | 어도비 일러스트레이터 원본 | 편집 가능한 마스터. 인쇄소·후속 디자이너가 요구 | 버전 호환 위해 CS6 이하 호환 저장본 동봉 권장 |
| **EPS** | 범용 벡터 교환 | 인쇄소·간판집·자수집이 가장 흔히 요구 | 구형 포맷이지만 현장 호환성 최고 |
| **SVG** | 웹 벡터 | 웹사이트, 앱, 무한 확대 | 폰트 미포함 → 아웃라인 필수. 뷰박스·불필요 메타데이터 정리 |
| **PDF** | 인쇄 표준 | 인쇄 입고, 클라이언트 확인용 | 벡터 유지 저장, 폰트 임베드 또는 아웃라인 |
| **PNG(투명)** | 래스터 + 알파 | PPT, 웹, SNS, 문서 삽입 | 여러 폭으로(예: 500/1000/2000/4000px) |
| **JPG** | 래스터, 불투명 | 흰 배경 전제 썸네일, 업로드 제한 대응 | 투명 불가. 로고 기본 배포용으로는 부적합 |

### 인쇄소가 실제로 요구하는 것
- "벡터 파일 주세요" → AI 또는 EPS, 간혹 PDF.
- "글자 깨짐 주세요" = **아웃라인화된 파일**.
- "CMYK로 주세요" → 색상 모드 변환본.
- "팬톤 몇 번이에요?" → 별색 지정 여부 확인.

### 아웃라인화를 반드시 하는 이유
글자가 폰트로 남아 있으면, 그 폰트가 설치되지 않은 컴퓨터에서 열 때 다른 폰트로 대체된다. 인쇄소 컴퓨터에는 대개 그 폰트가 없다. 결과는 자간·굵기·형태가 전부 어긋난 채로 인쇄되고, 아무도 사고를 눈치채지 못한 상태로 1,000장이 나온다.

추가 이유:
- **라이선스**: 폰트를 임베드해 넘기면 폰트 재배포로 볼 여지가 있다. 아웃라인화하면 글자가 아니라 도형이 된다.
- **불변성**: 클라이언트가 실수로 텍스트를 수정할 수 없다.

납품 시 **아웃라인본(배포용)** 과 **편집 가능 원본(폰트 살아있음, 내부 보관·수정용)** 을 나눠 두는 게 안전하다. 원본에 쓰인 폰트 이름과 라이선스 종류는 가이드에 반드시 적는다.

### 컬러모드
| 모드 | 쓰는 곳 | 비고 |
|---|---|---|
| RGB | 화면 전부(웹/앱/영상/PPT) | HEX로 함께 표기 |
| CMYK | 4도 인쇄 전반 | RGB 형광색은 CMYK에서 반드시 탁해진다. 인쇄 기준으로 먼저 잡고 화면색을 맞추는 편이 안전 |
| 별색(팬톤/Pantone) | 정확한 색 재현이 필요할 때 | 코팅지(C)/비코팅지(U) 번호가 다르다 |

### 별색이 필요한 경우
- 브랜드 색이 곧 자산일 때(색으로 인식되는 브랜드).
- 1~2색만 쓰는 인쇄물(봉투, 쇼핑백, 박스) — 4도보다 별색 1~2도가 싸고 색이 정확하다.
- CMYK로 재현 불가능한 색(형광, 진한 오렌지·바이올렛, 금·은).
- 자수 실색, 시트지 색상 매칭의 기준값으로.

정확한 팬톤 번호는 모니터가 아니라 **실물 컬러칩과 인쇄 시험**으로 확정한다. 화면에서 찍은 번호는 참고값이다.

## 3. 로고 변형 세트 (variations)

| 변형 | 형태 | 실제 사용처 |
|---|---|---|
| 조합형 가로 | 심볼 + 워드마크 좌우 배치 | 웹 헤더, 명함, 문서 레터헤드, 배너 — 가로 공간이 넉넉한 기본형 |
| 조합형 세로 | 심볼 위, 워드마크 아래 | 정사각 공간, 간판, 포스터 중앙 배치, 스탬프, 패키지 정면 |
| 심볼 단독 | 아이콘만 | 앱 아이콘, 파비콘, SNS 프로필, 굿즈 자수, 워터마크, 인지도 쌓인 뒤의 축약 표기 |
| 워드마크 단독 | 글자만 | 심볼이 안 보이는 초소형 가로 공간, 협찬사 나열, 텍스트 위주 문서 |
| 1색 흑백(먹 1도) | 검정 단색 | 팩스, 복사, 신문 광고, 스탬프, 각인, 영수증, 계약서 |
| 반전(화이트/녹아웃) | 흰색 단색 | 어두운 배경, 사진 위, 어두운 간판, 굿즈 |
| 최소크기 전용 단순화판 | 디테일 제거·선 굵기 보정 | 파비콘, 자수, 각인, 10mm 이하 적용 |

**단순화판이 별도로 필요한 이유**: 원본을 그냥 축소하면 얇은 선이 사라지고 내부 여백이 메워진다. 축소 전용 버전은 선을 굵히고, 내부 홈을 넓히고, 잔디테일을 지운 별개의 파일이다. 같은 로고로 보이되 같은 파일이 아니다.

각 변형은 최소한 **컬러 / 흑백 / 반전** 3종으로 파생시킨다. 조합형 가로만 해도 3개 파일이 나온다.

### 폴더 구조 예시
```
브랜드명_로고/
├─ 01_벡터원본/       AI, EPS (아웃라인 / 편집용 분리)
├─ 02_웹/             SVG, PNG(투명, 다중 해상도)
├─ 03_인쇄/           PDF(CMYK), EPS(CMYK), 별색본
├─ 04_변형/           가로·세로·심볼·워드마크 × 컬러·흑백·반전
├─ 05_디지털규격/     파비콘, 앱아이콘, OG, SNS 프로필
└─ 06_가이드/         브랜드 가이드 PDF
```

## 4. 브랜드 가이드에 반드시 들어갈 항목

### 여백 규칙 (clear space)
로고 주변에 아무것도 넣지 않는 최소 영역. **기준 단위는 로고 자체의 요소에서 뽑는다** — 로고가 커지든 작아지든 비율이 유지되기 때문이다.

흔한 기준:
- 워드마크의 대문자 높이(X) 또는 첫 글자 폭
- 심볼의 높이 또는 폭의 1/2
- 심볼 내부의 특징적 요소(원, 획 굵기)

표기 예: "로고 사방에 심볼 높이의 1/2(= X) 이상 여백을 둔다."

### 최소 크기

| 매체 | 기준 | 통용 범위 | 비고 |
|---|---|---|---|
| 인쇄(오프셋) | 로고 전체 폭 | 15~25mm | 워드마크 가독성 기준 |
| 인쇄, 심볼 단독 | 심볼 높이 | 6~10mm | |
| 화면 | 로고 전체 폭 | 80~120px | 워드마크 포함 시 |
| 화면, 심볼 단독 | 높이 | 24~32px | |

실제 값은 로고 형태(획 굵기, 글자 수)에 따라 다르다. **확정 방법은 실측**이다 — 최소 크기 후보로 출력해서 눈으로 읽히는지 본다. 화면은 실제 기기에서 확인한다.

### 컬러값
로고 색마다 4종 전부 표기한다.

| 색 이름 | HEX | RGB | CMYK | Pantone |
|---|---|---|---|---|
| 프라이머리 | #______ | __, __, __ | __, __, __, __ | ___ C / ___ U |
| 세컨더리 | | | | |
| 블랙(먹) | | | | |

CMYK 값을 RGB에서 자동 변환한 채로 두면 인쇄 결과가 어긋난다. 인쇄 기준값을 별도로 정한다.

### 지정 폰트와 대체 폰트
- 로고에 쓰인 폰트명 + 웨이트 + **라이선스 종류**(상업 사용 범위, 웹폰트 허용 여부)
- 브랜드 본문/제목용 지정 폰트
- 대체 폰트: 지정 폰트를 못 쓰는 환경(웹, 오피스 문서, 외주 협력사)용 대안 1~2종. 무료·시스템 폰트에서 고르는 게 현실적이다.

### 금지 사용 예시 (최소 8가지)
1. 가로세로 비율 왜곡 (한쪽만 늘이기)
2. 임의 색상 변경 (지정 컬러 외 사용)
3. 로고 회전·기울임
4. 그림자·외곽선·글로우·엠보싱 등 효과 추가
5. 심볼과 워드마크의 배치·간격 임의 변경
6. 지정 폰트가 아닌 폰트로 워드마크 재타이핑
7. 여백 규칙 침범 (다른 요소·이미지 경계가 여백 안으로 들어옴)
8. 대비 부족한 배경 위 사용 (비슷한 명도의 배경, 복잡한 사진 위)
9. 최소 크기 이하로 축소
10. 로고에 문구·슬로건·태그라인 임의 추가
11. 로고를 도형·박스 안에 임의로 가두기
12. 로고 일부만 잘라 쓰기, 심볼 임의 크롭
13. 그라디언트·패턴·사진을 로고 안에 채우기
14. 다른 로고와 붙여 하나의 잠금(lockup)처럼 쓰기

각 항목은 **잘못된 예시 이미지**와 함께 보여준다. 글로만 쓰면 지켜지지 않는다.

## 5. 제작 공법별 제약표 (핵심)

수치는 실무에서 흔히 통용되는 범위다. **정확한 값은 반드시 실제 시공/제작 업체에 확인한다.** 같은 공법도 장비·소재에 따라 한계가 다르다.

| 공법 | 제약 | 형태에 미치는 영향 |
|---|---|---|
| **자수 (Embroidery)** | 최소 선/획 굵기 약 1~1.5mm, 최소 글자 높이 약 5~7mm. 색상 수는 실 교체 = 비용. 곡선·미세 각도가 뭉개짐 | 가는 획·헤어라인·세리프 소실. 그라디언트 불가(색 단계 분리 필요). 글자 사이 좁은 여백이 실로 메워짐 → 자간 넓힌 자수 전용 버전 필요 |
| **실크스크린 1도 인쇄** | 단일 색. 미세 망점·얇은 선 재현 한계(대략 0.25mm 이상 권장). 소재(천/유리/플라스틱)에 따라 번짐 | 그라디언트·다색 불가 → 1색 버전 필수. 음각(파낸 흰 선)이 잉크로 메워짐. 반전 로고는 흰 여백을 더 넓혀야 함 |
| **스탬프 (고무도장)** | 최소 선 굵기 약 0.3~0.5mm, 반대로 최소 여백(선 사이 간격)도 유사 하한. 잉크 번짐 | 얇은 선은 안 찍히고, 촘촘한 선은 뭉쳐서 덩어리가 됨. 면적 큰 검정은 얼룩짐 → 선 위주 단순화판 필요 |
| **채널사인 (외벽 간판, 입체 글자)** | 글자 하나하나가 독립 구조물. 획 굵기가 얇으면 제작·설치 불가(통용 하한 대략 20~30mm 폭, 크기에 비례). 내부 LED 공간 필요. 글자 분리 필수 | 획이 끊긴 글자, 서로 겹친 글자, 얇은 세리프는 제작 곤란. 카운터(글자 속 구멍)가 작으면 막힘. 밤에는 빛나는 면만 보인다 → 실루엣만으로 읽히는지 검증 |
| **시트지 커팅 (Vinyl cut)** | 칼날이 지나갈 경로가 필요. 최소 선 굵기 약 1~2mm, 미세 섬은 떨어짐. 반드시 단색 | 얇은 획·점·작은 카운터가 시공 중 떨어져 나감. 그라디언트 불가. 속 뚫린 글자(ㅇ, ㅁ, O, A)는 내부 조각 고정 문제 |
| **각인 / 음각 (레이저·타공·엠보)** | 소재별 편차 큼. 선 굵기 하한 약 0.3~0.8mm. 깊이가 얕으면 안 보임 | 색이 없다 → **명암·형태만으로 식별되어야 함**. 색 대비에 의존한 로고는 각인에서 사라진다. 세밀한 디테일은 뭉개짐 |
| **패키지 곡면 라벨** | 곡면 왜곡, 라벨 끝단 재단 오차(통상 2~3mm), 접합부 | 로고가 곡면에서 휘어 보임. 가로로 긴 로고일수록 왜곡 큼 → 세로형/심볼 단독 유리. 재단 오차 대비 여백 확보 필수 |
| **팩스·복사 열화** | 저해상도 흑백 이진화. 중간 톤이 검정 또는 흰색으로 날아감 | 회색·연한 색은 사라지거나 통째로 검정. 얇은 선 끊김, 좁은 여백 메워짐 → 1색 버전이 그대로 견디는지 확인(복사기로 3회 복사 테스트) |
| **파비콘 / 앱아이콘** | 16×16px까지 축소. 픽셀 그리드에 걸림 | 워드마크는 절대 안 읽힘 → 심볼 단독 필수. 디테일 2~3개 이상이면 얼룩. 대각선·곡선이 계단현상. 단순화판 필요 |
| **자동차 랩핑** | 곡면·굴곡·문틈·손잡이·유리 경계. 원거리에서 순간 인식 | 로고가 굴곡에 걸려 왜곡·절단됨. 배치 가능 평면 영역이 제한적 → 세로형/심볼 단독 유리. 주행 중 0.5초에 읽히는 굵기 필요 |

### 이 표를 쓰는 법
로고를 확정하기 **전에** 클라이언트가 실제로 쓸 공법을 물어본다. 자수 굿즈를 만들 브랜드라면 헤어라인 세리프 로고를 뽑아선 안 된다. 공법 목록이 로고 형태의 제약조건이지, 로고를 만들고 나서 맞추는 게 아니다.

**공통 스트레스 테스트** (전부 통과해야 함):
1. 16px로 축소해서 알아볼 수 있는가
2. 완전 흑백 1도로 바꿔도 형태가 유지되는가
3. 흑백을 반전해도 무너지지 않는가
4. 흐리게(blur) 만들었을 때 실루엣이 구분되는가
5. 팩스 3회 복사에서 살아남는가

## 6. 디지털 규격

| 용도 | 크기 | 잘리는 방식 | 대응 |
|---|---|---|---|
| **파비콘** | 16, 32, 48px (ICO 다중 + SVG + PNG) | 안 잘리지만 픽셀이 없다 | 심볼 단독 단순화판. 16px에서 형태 확인은 실제 브라우저 탭에서 |
| **iOS 앱아이콘** | 1024×1024 마스터 | 시스템이 **라운드 스퀘어(superellipse)** 로 마스크. 모서리 잘림 | 투명 배경 금지(불투명 배경 필수). 심볼을 중앙에, 가장자리 약 10% 이상 여백 |
| **Android 적응형** | 108×108dp 레이어(전경/배경), 실제 표시 영역 72×72dp | 런처가 원·둥근사각·물방울 등 임의 모양으로 마스크. **안전영역은 중앙 약 66%** | 로고는 안전영역 안에만. 바깥 33%는 시차 효과로 잘려 나가는 여유분 |
| **OG 이미지** | 1200×630 (1.91:1) | 플랫폼별 재크롭(양옆 또는 상하 잘림) | 텍스트·로고를 중앙 안전영역에 배치. 가장자리는 배경만 |
| **인스타 프로필** | 업로드 정사각, 표시는 **원형 크롭** | 정사각의 모서리 4곳 전부 잘림 | 심볼 단독을 원 안에 들어가게 배치. 가로 워드마크는 양끝 잘림 → 쓰지 말 것 |
| **카카오톡 채널 프로필** | 정사각 업로드, 표시는 원형/둥근사각 | 인스타와 동일한 문제 | 심볼 단독 + 여백. 채널 홈 배경 이미지는 별도 규격 확인 |
| **유튜브/기타 SNS 프로필** | 정사각 → 원형 | 동일 | 프로필용 정사각 캔버스 파일을 별도로 만들어 둔다 |

**공통 원칙**: 프로필류는 전부 원형으로 잘린다고 가정한다. 정사각 캔버스에 심볼을 넣고, 원을 그려 안에 들어오는지 확인한 파일을 별도로 납품한다. 로고 벡터를 그대로 정사각에 꽉 채워 주면 클라이언트가 잘린 채로 쓴다.

## 7. 계약·저작권 최소 상식

**법률 조언이 아니라 실무 관행 정리다.** 금액이 크거나 분쟁 소지가 있으면 변호사·변리사에게 확인한다. 한국 기준.

### 저작권 양도 vs 사용허락

| 구분 | 저작권 양도 | 사용허락(라이선스) |
|---|---|---|
| 권리 | 재산권이 클라이언트에게 넘어감 | 디자이너가 권리 보유, 클라이언트는 정해진 범위로 사용 |
| 범위 | 원칙적으로 제한 없음 | 매체·기간·지역 등 계약서에 쓴 범위 안 |
| 수정·2차 저작물 | **2차적저작물작성권은 별도로 명시하지 않으면 양도되지 않은 것으로 추정된다** → 넘길 거면 계약서에 따로 적는다 | 대개 불가 |
| 디자이너의 포트폴리오 사용 | 양도해도 관행상 허용받는 경우가 많으나 **계약서에 적어야 안전** | 통상 가능 |
| 가격 | 높음 | 낮음 |

**저작인격권(성명표시권·동일성유지권 등)은 양도 대상이 아니다.** 실무에서는 "저작인격권을 행사하지 않는다"는 조항으로 처리하는 경우가 많다.

### 소스파일 제공 여부가 가격을 가르는 이유
벡터 원본을 넘기면 클라이언트가 **직접 수정하고, 확장하고, 다른 디자이너에게 넘길 수 있다.** 그 시점부터 디자이너는 후속 수주에서 빠진다. 저가 티어가 PNG만 주는 건 인색해서가 아니라 그게 가격 구조다. 소스파일 제공 = 사실상 권리 이전에 준하는 효과라는 걸 클라이언트에게 설명하고 가격에 반영한다.

### 상표 출원은 디자이너 업무가 아니다
- 로고 저작권과 **상표권은 별개**다. 저작권이 있어도 남이 같은 업종에 먼저 상표 등록하면 사용에 문제가 생길 수 있다.
- 출원·등록 대리는 **변리사의 업무**다. 디자이너가 대행하거나 등록 가능성을 보장하면 안 된다.
- 넘겨야 할 말: "상표 등록은 별도이며 변리사 상담을 권합니다. 저는 등록 가능 여부를 보장하지 않습니다."
- **선행상표 조사도 보장하지 말 것.** 특허청 키프리스(KIPRIS) 검색을 참고로 해볼 수는 있으나, 결과에 대한 책임은 지지 않는다고 명시한다.
- 폰트·소재의 상업적 사용 라이선스는 디자이너 책임 영역이다. 이건 확인해야 한다.

### 수정 횟수 명시
분쟁의 대부분은 여기서 난다.

- 총 수정 횟수를 숫자로 적는다. (예: 시안 확정 후 3회)
- **1회의 정의를 적는다.** "한 번에 취합해 전달한 피드백 = 1회". 카톡으로 하루 종일 찔끔찔끔 오는 건 1회가 아니다.
- **방향 전환은 수정이 아니다.** 컨셉을 뒤엎는 요구는 추가 비용 항목으로 분리한다.
- 초과 시 추가 비용을 미리 금액으로 적는다.
- 최종 컨펌 이후의 수정은 별건임을 적는다.
- 작업 기간과 응답 기한(클라이언트가 O일 내 회신)도 함께 적는다. 연락 두절 시 처리 방법까지.

## 부록 · 벡터 원본을 망치지 않는 규칙

납품 시점이 아니라 **작업 내내** 지킨다. 어긴 채로 진행하면 되돌릴 수 없다.

| 규칙 | 어기면 |
|---|---|
| 원은 원(ellipse)으로, 선은 선(stroke)으로 유지한다 | 아웃라인화한 형태는 앵커 덩어리가 되어 획 굵기를 못 고친다 |
| 아웃라인화(글자→패스, 선→면)는 **납품 직전 사본에서만** 한다 | 원본 편집 능력을 잃는다. 원본은 항상 살아있는 상태로 보관 |
| 곡선의 앵커는 필요한 최소 개수로 유지한다 | 앵커가 많으면 축소 시 울퉁불퉁해지고, 어느 앵커를 옮겨야 할지 알 수 없게 된다 |
| 도형을 합칠 때 불리언 결과를 바로 확정하지 않는다 | 되돌릴 수 없다. 원본 도형을 복제해두고 합친다 |
| 자동 벡터 변환(이미지 추적) 결과를 그대로 쓰지 않는다 | 앵커 수백 개. 수정 불가능한 형태가 된다 |

### 브라우저 print-to-PDF로 `.ai`를 만들려는 경우 (실측)

동작하지 않는다. 헤드리스 크롬 출력 내부를 열어본 결과, 원 1개가 베지어 128개로 쪼개지고 stroke가 fill로 눌린다. 벡터이긴 하나 편집 불가능한 파일이다.

SVG 경로를 PDF 연산자로 1:1 매핑하는 라이브러리를 쓰면 형태와 stroke는 보존된다. 다만 CMYK·별색·레이어 구조는 이 방법으로도 못 넘는다. 정밀 인쇄 납품이 필요하면 일러스트레이터가 답이다.

### 여백 규칙을 도해할 때 — `getBBox()`를 믿지 마라

clear space 도해에서 점선 박스는 **잉크의 실제 경계**에 맞물려야 한다. 그런데 SVG `getBBox()`는 회전된 호나 곡선을 **베지에 제어점 기준**으로 재기 때문에 실제 잉크보다 크게 나온다.

실측 예: 회전된 열린 호 3개로 된 심볼에서 `getBBox()` 161×141.5 vs 실제 잉크 143.4×116.4 — 12% 과대. 그대로 쓰면 점선과 심볼 사이에 가짜 틈이 생겨 여백 규칙 자체가 틀린 문서가 된다.

**대응**: 심볼을 캔버스에 크게(1600px 정도) 그린 뒤 **알파 픽셀을 스캔해 실경계를 구한다.** 이게 여백·최소크기·광학 중심 계산의 기준이 된다.

### 최소 크기 견본을 2x로 출력할 때

가이드 시트를 레티나(2x)로 뽑으면 "16px 견본"이 파일 안에서는 32px가 된다. 정상이지만 보는 사람이 헷갈린다. **시트 안에 "화면 견본은 CSS 픽셀 기준"이라고 적어둔다.**
