# 요청 문장 카드 — Claude에게 로고 작업 시키는 법

복사해서 그대로 쓰는 문장 모음이다. 읽지 말고 필요한 카드를 찾아 붙여넣어라.

---

## 1. 왜 결과가 엉뚱하게 나오나

Claude는 맥락이 없으면 평균적인 답을 준다. "로고 만들어줘"에는 조건이 하나도 없으니 아무 브랜드에나 붙는 무난한 말이 돌아온다.
좋은 요청은 세 가지가 들어간다. ①무엇을 ②어떤 조건에서 ③어떤 형태로 받을지.
이 셋 중 하나라도 빠지면 받은 걸 버리고 다시 시키게 된다. 처음에 두 줄 더 쓰는 게 싸다.

**작업 전제**: 케이스는 8개, 각각 가상 클라이언트 브리프가 있다. 작업 파일은 Figma다. Claude는 Figma MCP로 그 파일을 읽고 쓸 수 있다.
**AI 경계선**: 납품물은 벡터(SVG/AI) + 사용 가이드다. 이미지 생성 AI는 래스터라 납품이 안 된다. AI는 컨셉 발산 / 무드보드 / 목업 합성 / 문서 조판까지다. **로고 형태 드로잉은 내가 피그마에서 직접 한다.**

## 2. 문장 카드

### 상황: 경쟁사 조사 시키기

❌ 이렇게 말하면
```
베이커리 로고들 좀 찾아줘
```
→ 예쁜 로고 링크 목록이 온다. 내 차별화 판단에는 못 쓴다.

✅ 이렇게 말해라
```
케이스 01은 동네 베이커리 "밀과달"다. 반경 2km 경쟁 상권에 있을 법한
베이커리 브랜드 8곳을 찾아서 표로 정리해줘. 열은 이렇게: 브랜드명 / 로고 유형
(워드마크·심볼+워드·모노그램·엠블럼) / 주된 형태 요소 / 서체 분류(세리프·산세리프·스크립트) /
주색상. 마지막에 8곳에서 반복되는 클리셰 3개를 뽑아줘. 그게 내가 피해야 할 형태다.
```
→ 내가 뭘 안 그려야 하는지가 목록으로 나온다. 합격기준 ④(실루엣 차별)의 근거가 된다.

---

### 상황: 무드보드용 이미지 만들기

❌ 이렇게 말하면
```
베이커리 무드보드 만들어줘
```
→ 스톡사진 같은 빵 사진이 나온다. 형태 언어에 대한 정보가 0이다.

✅ 이렇게 말해라
```
케이스 01 "밀과달" 무드보드용 이미지 6장을 만들어줘. 로고가 아니라 "질감과 태도"
레퍼런스다. 조건: 로고·글자·심볼은 절대 넣지 마. 흑백 또는 2색까지만.
6장은 각각 — ①오래된 나무 반죽대 표면 ②밀가루가 뿌려진 검은 철판 ③손으로 찢은 종이 가장자리
④크래프트 종이봉투 접힌 자국 ⑤창으로 들어온 아침 사선 빛 ⑥가마 벽돌의 거친 면.
각 장 밑에 "이 이미지에서 로고로 가져갈 형태 특성" 한 줄씩 적어줘.
```
→ 컨셉 발산의 재료가 된다. 이미지 자체는 납품물이 아니라 참고 벽이다.

---

### 상황: 컨셉/방향 발산 시키기 (형태를 그려달라는 게 아니다)

❌ 이렇게 말하면
```
밀과달 로고 아이디어 좀 줘
```
→ "밀 이삭을 형상화한 심볼" 같은 걸 3개 준다. 전부 이미 남이 한 것이다.

✅ 이렇게 말해라
```
케이스 01 "밀과달" 브리프를 읽고 로고 방향을 12개 내줘. 형태를 그리지 말고
"방향"만 줘. 각 방향은 이 3줄 형식으로:
- 개념 한 단어
- 왜 이 브랜드에 맞는지 한 문장 (브리프의 어느 문장에서 나왔는지 인용)
- 형태로 옮길 때의 조형 규칙 한 문장 (예: 획 굵기 일정, 45도만 사용, 곡률 반경 하나로 통일)
직전 조사에서 뽑은 클리셰 3개(밀 이삭·둥근 배지·스크립트 필기체)를 쓴 방향은 빼줘.
```
→ 내가 피그마에서 그릴 출발점 12개가 나온다. 형태는 내가 만든다.

---

### 상황: 내 시안을 비평받기 ★ 가장 중요

❌ 이렇게 말하면
```
이 로고 어때?
```
→ "깔끔하고 모던합니다" 같은 소리가 온다. 아무 정보가 없다.

✅ 이렇게 말해라
```
피그마 파일 [URL]의 "case01/round2" 프레임을 읽어줘. 케이스 01 "밀과달" 시안 4개다.
칭찬은 하지 마. 각 시안마다 문제점만 3개씩 지적해줘. 지적은 반드시 이 형식으로:
"어디가(구체적 부위) / 무엇이 문제인지 / 어떻게 고칠 수 있는지"
그리고 6개 합격기준으로 통과·탈락 판정해줘: ①16px에서 식별되나 ②흑백 1색으로 성립하나
③반전(어두운 배경)에서 성립하나 ④경쟁사 3곳과 실루엣이 구분되나 ⑤형태의 이유를 한 문장으로
설명 가능한가 ⑥ 판정 근거를 한 줄씩.
탈락 항목이 하나도 없는 시안이 있으면 "왜 탈락이 없는지" 의심해서 다시 봐줘.
```
→ 고칠 곳이 부위 단위로 나온다. 마지막 문장이 형식적 통과를 막는다.

---

### 상황: 시안 중 하나를 고르기

❌ 이렇게 말하면
```
셋 중에 뭐가 제일 나아?
```
→ Claude가 하나 골라준다. 근거는 얕고, 내가 왜 골랐는지 설명할 수 없게 된다.

✅ 이렇게 말해라
```
케이스 01 시안 A·B·C 중에서 대신 고르지 마. 내가 고를 수 있게 근거만 정리해줘.
① 6개 합격기준 × 3시안 표로 O/X와 한 줄 근거
② 각 시안이 브리프의 어느 요구를 만족시키고 어느 요구를 버렸는지
③ 각 시안을 골랐을 때 앞으로 3개월 안에 터질 문제 (간판·앱아이콘·자수·1색 도장)
④ 결정을 가르는 질문 1개 — 내가 이 질문에 답하면 선택이 정해지는 그런 질문
```
→ 선택은 내가 하고, 포트폴리오에 쓸 "왜 이걸 골랐나"가 같이 남는다.

---

### 상황: 색 팔레트 정하기

❌ 이렇게 말하면
```
따뜻하고 감성적인 색 골라줘
```
→ 베이지 계열 5개가 온다. 왜 그 색인지도, 어디에 쓰는지도 없다.

✅ 이렇게 말해라
```
케이스 01 "밀과달" 팔레트를 짜줘. 조건:
- 주색 1 + 보조 1 + 중립 2. 그 이상은 만들지 마.
- 로고는 흑백 1색으로 먼저 성립해야 한다. 색은 나중에 얹는 것이다.
- 주색은 흰 배경/검정 배경 양쪽에서 4.5:1 대비를 넘겨야 한다. HEX와 대비값 같이 줘.
- 경쟁사 조사에서 나온 주색들과 색상환에서 30도 이상 떨어져야 한다.
- 각 색마다 "어디에 쓰는 색인지" 한 줄 (간판·포장·앱·인쇄 1색 대체).
CMYK 근사값과 인쇄 1색으로 떨어뜨릴 때의 대체 그레이도 같이.
```
→ 가이드 문서에 그대로 들어가는 표가 나온다.

---

### 상황: 폰트 후보 고르기

❌ 이렇게 말하면
```
어울리는 폰트 추천해줘
```
→ 유료 폰트나 라이선스 불명 폰트가 섞여 온다. 케이스 진행이 막힌다.

✅ 이렇게 말해라
```
케이스 01 "밀과달" 워드마크 베이스로 쓸 서체 후보 5개를 줘. 조건:
- 상업적 사용 가능하고 로고 변형(outline 후 커브 수정) 허용하는 라이선스만. 라이선스명 명시.
- 한글 "밀과달" + 영문 "MILGWA NAMU" 둘 다 있는 서체 우선. 없으면 짝지을 한글 서체를 같이.
- 5개는 서로 성격이 겹치지 않게 (예: 인간적인 세리프 / 기하 산세 / 그로테스크 / 조판체 / 각진 옛활자)
각 후보마다: 왜 이 브랜드에 맞는지 한 줄 / 이 서체를 로고로 쓸 때 손대야 할 글자 부위 한 줄
(예: ㅁ 모서리 곡률, R의 다리, 자간).
```
→ 다운로드해서 바로 아웃라인 딸 수 있는 후보가 나온다.

---

### 상황: 피그마 파일에 작업 공간 만들어달라기

❌ 이렇게 말하면
```
피그마 좀 세팅해줘
```
→ 프레임 몇 개가 아무렇게나 생긴다.

✅ 이렇게 말해라
```
피그마 파일 [URL]에 케이스 01 작업 페이지를 만들어줘. 구조:
- 페이지명 "01_밀과달"
- 프레임 ①brief(브리프 텍스트) ②research(경쟁사 표) ③mood(무드보드 6장 그리드)
  ④sketch(1000x1000 아트보드 30개, 5x6 그리드, 각 40px 라벨 s01~s30)
  ⑤검증(16px·흑백·반전 미리보기 슬롯 3개)
- 검증 프레임은 sketch에서 컴포넌트 인스턴스를 끌어다 놓으면 자동으로 축소/흑백으로 보이게
  프레임 크기와 배경만 미리 잡아줘
로고 형태는 하나도 그리지 마. 빈 아트보드와 라벨만.
```
→ 그리기만 하면 되는 판이 깔린다. 마지막 줄이 경계선을 지킨다.

---

### 상황: 만든 SVG를 검증받기

❌ 이렇게 말하면
```
이 SVG 확인해줘
```
→ "문제없어 보입니다"가 온다.

✅ 이렇게 말해라
```
첨부한 milgwa-namu.svg를 코드 레벨에서 점검해줘:
① 남아있는 열린 패스·겹친 노드·중복 패스가 있나
② 획(stroke)이 남아있나 — 전부 fill로 아웃라인 확정돼야 한다
③ 텍스트 요소가 남아있나 — <text>가 하나라도 있으면 실패다
④ 소수점 좌표 자리수, viewBox 정합, 불필요한 transform/group 중첩
⑤ 16x16으로 렌더했을 때 뭉개져 사라지는 디테일이 어디인지
⑥ fill을 전부 #000으로 바꿨을 때 형태가 붙어버리는(메워지는) 구간
고칠 곳은 패스 인덱스나 좌표로 짚어줘. 파일은 네가 고치지 말고 목록만 줘.
```
→ 피그마로 돌아가서 고칠 목록이 나온다.

---

### 상황: 브랜드 가이드 문서 조판시키기

❌ 이렇게 말하면
```
브랜드 가이드 만들어줘
```
→ 목차만 그럴듯한 빈 문서가 나온다.

✅ 이렇게 말해라
```
케이스 01 "밀과달" 브랜드 가이드를 조판해줘. 내용은 내가 준 것만 쓰고, 없는 항목은
"[미정]"으로 남겨. 지어내지 마.
구성: 표지 / 로고의 이유(한 문장) / 기본형·조합형 / 최소 크기(16px 근거) /
여백 규정(x-height 기준) / 색 규정(주1 보조1 중립2, HEX·CMYK) / 흑백·반전 사용 /
금지 사용 8종(늘리기·회전·그림자·그라디언트·테두리·색변경·재배열·저대비 배경) /
적용 예시.
형식은 A4 세로 HTML 한 파일로, 인쇄 시 페이지 안 깨지게. 로고 이미지는 <img src="">
자리표시자로 두고 파일명만 주석으로 적어줘.
```
→ 로고 파일만 끼우면 끝나는 문서가 나온다.

---

### 상황: 목업 만들기

❌ 이렇게 말하면
```
목업 좀 만들어줘
```
→ 로고가 잘 보이는 예쁜 사진이 나온다. 검증에는 쓸모없다.

✅ 이렇게 말해라
```
케이스 01 로고 목업을 만들어줘. 잘 나온 컷 말고 "가혹한 조건" 컷으로 5장:
①밤 간판 — 역광, 로고가 실루엣으로만 보이는 상태
②크래프트 종이봉투 1색 인쇄 — 잉크 번짐 있는 상태
③앱 아이콘 60x60 — 홈화면 다른 아이콘 사이에 낀 상태
④앞치마 자수 — 실 굵기 때문에 얇은 선이 뭉개진 상태
⑤영수증 흑백 감열지 — 저해상도 도트
로고는 내가 준 SVG를 그대로 합성해. 형태를 다시 그리거나 보정하지 마.
각 컷마다 "여기서 무너진 부분" 한 줄씩.
```
→ 합격기준 ①②③을 눈으로 확인하는 증거가 나온다.

---

### 상황: 포트폴리오용 케이스 설명 글 쓰기

❌ 이렇게 말하면
```
포트폴리오 글 써줘
```
→ "따뜻한 감성을 담아냈습니다" 같은 자기소개서가 나온다.

✅ 이렇게 말해라
```
케이스 01 "밀과달"의 포트폴리오 케이스 글을 써줘. 형용사 금지 — 따뜻한, 감성적인,
모던한, 세련된 이런 단어 쓰면 다시 쓴다. 대신 결정과 근거만.
구조:
① 문제 한 문단 (브리프에서 뽑은 제약 3개)
② 버린 방향 3개와 각각을 버린 이유 (실제로 내가 버린 시안 이름으로)
③ 최종 형태의 이유 한 문장
④ 검증 — 16px / 흑백 / 반전 / 경쟁사 실루엣 비교, 각 한 줄
⑤ 숫자 한 줄 (시안 34개 중 1개)
내가 준 작업 기록에 없는 사실은 절대 쓰지 마. 부족하면 "여기에 무엇을 알려달라"고 물어봐.
```
→ 심사자가 읽을 글이 나온다. ⑤가 합격기준 ⑥의 증거다.

---

### 상황: 막혔을 때 (아이디어가 안 나올 때)

❌ 이렇게 말하면
```
아이디어가 안 나와. 뭐 해야 돼?
```
→ 일반적인 창작 조언이 온다.

✅ 이렇게 말해라
```
케이스 01에서 시안 18개 그렸는데 전부 비슷하다. 밀 이삭 아니면 나무 실루엣이다.
아이디어를 주지 말고, 내가 다르게 그리게 만드는 "제약"을 12개 줘.
제약은 형태를 지정하지 말고 규칙만 지정할 것. 예시 형식:
"직선만 사용, 곡선 금지" / "닫힌 도형 2개 이하" / "글자에서만 형태를 뽑을 것"
/ "여백이 형태가 되게" / "한 획으로 그릴 것"
내가 이미 쓴 접근(이삭·나무·둥근배지)을 강화하는 제약은 빼줘.
```
→ 그리기 시작할 수 있는 규칙이 나온다. 형태는 여전히 내가 만든다.

---

### 상황: AI가 대신 그려주려 할 때 막는 법

❌ 이렇게 말하면
```
그럼 네가 로고 시안 몇 개 뽑아봐
```
→ 래스터 이미지가 나온다. 납품 불가고, 그걸 따라 그리면 내 형태가 아니게 된다.

✅ 이렇게 말해라 (작업 시작할 때 한 번 박아둘 문장)
```
이 프로젝트에서 너는 로고 형태를 만들지 않는다. 규칙:
- 이미지 생성으로 로고·심볼·마크·워드마크를 만들지 마.
- SVG 패스로 로고 형태를 직접 작성하지 마.
- 피그마에 도형을 그려서 로고 형태를 만들지 마.
로고 드로잉은 내가 피그마에서 한다. 네 역할은 조사·발산·비평·검증·조판·목업합성이다.
내가 실수로 "그려줘"라고 하면 거절하고, 대신 무엇을 해줄 수 있는지 물어봐.
```
→ 이후 요청이 흔들려도 경계선이 유지된다.

## 3. 어떤 말을 하면 안 되는가

| 금지어 | 왜 | 대신 |
|---|---|---|
| "알아서 해줘" | 조건이 없으면 평균값이 온다 | 조건 3개를 써라 — 목적 / 제약 / 받을 형식 |
| "예쁘게" | 측정할 수 없다 | "16px에서 형태가 유지되게" |
| "감성적으로" | 측정할 수 없다 | "손으로 그은 듯한 불균일한 획, 좌우 비대칭 허용" |
| "고급스럽게" | 측정할 수 없다 | "장식 요소 0개, 색 2개 이하, 여백 비율 40% 이상" |
| "깔끔하게" | 측정할 수 없다 | "닫힌 도형 3개 이하, 곡률 반경 1종류로 통일" |
| "로고 그려줘" | AI 경계선 위반. 래스터는 납품 불가고, AI가 그린 형태는 내 결정이 아니다 | "이 방향으로 그릴 때 지켜야 할 조형 규칙 5개를 줘" |
| "트렌디하게" | 3년 뒤 죽는다 | "2015년에 만들었어도 지금 살아있을 형태 조건" |

## 4. 결과가 마음에 안 들 때 되돌리는 말

"다시 해줘"는 같은 걸 또 받는다. 무엇이 왜 안 맞는지 말해라.

```
1. 12개 방향 중 7개가 "밀"에서 출발했다. 재료 은유를 빼고 다시 12개 줘.
   대신 "매일 같은 시간에 연다"는 브리프 문장에서 출발해줘.

2. 비평이 전부 "조금 더 다듬으면 좋겠다" 수준이다. 부위를 짚어줘.
   "s07의 왼쪽 아래 곡선이 획 굵기가 30% 얇아져서 16px에서 끊긴다" 이 정도로.

3. 팔레트 5개 중 3개가 경쟁사 A와 색상 차이 15도 이내다. 조사 결과를 다시 읽고
   30도 조건을 만족하는 것만 줘.

4. 목업이 전부 로고가 잘 보이게 나왔다. 그건 검증이 아니다.
   로고가 무너지는 조건으로 다시 만들어줘.

5. 케이스 글에 내가 말한 적 없는 "3주간의 리서치"가 들어갔다. 지어낸 문장 전부 지우고,
   근거가 없는 자리는 [확인 필요]로 남겨줘.
```

공통 규칙: **어디가 / 왜 / 대신 무엇을** 세 개를 붙여라.
