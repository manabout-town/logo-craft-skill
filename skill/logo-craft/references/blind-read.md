# 블라인드 읽힘 테스트

로고가 **무엇으로 읽히는지**를 재는 절차. 검증 시트가 못 재는 유일한 것이고, 실패하면 나머지가 다 무의미해진다.

## 왜 필요한가

만든 사람은 자기 로고가 뭐로 보이는지 판정할 수 없다. 이미 답을 알고 보기 때문이다. "옹이"라고 생각하며 그린 형태는 만든 사람 눈에는 영원히 옹이로 보인다.

실제 사례: 검증 6개를 전부 통과한 심볼이 목업 단계에서 **새 옆모습**으로 읽히는 게 드러났다. 그 전에 이 테스트를 했다면 정제 단계에서 잡혔다.

## 절차

### 1. 자극 만들기

```bash
node ~/.claude/skills/logo-craft/assets/blind-stimulus.mjs <로고.svg>
```

기본 / 축소(36px) / 반전 3장이 나온다. SVG의 `<title>` `<desc>` `id` 주석이 전부 제거되고 파일명도 무작위가 된다.

**누설 차단이 이 테스트의 전부다.** 하나라도 새면 결과가 쓸모없어진다.

- 브랜드명·업종·컨셉을 말하지 않는다
- 파일 경로에 브랜드명이 들어간 폴더를 쓰지 않는다
- "카페 로고인데요" 같은 힌트도 금지 — 업종을 알면 답이 그쪽으로 끌린다
- 이전에 이 로고를 본 사람은 리더가 될 수 없다

### 2. 질문 — 이 문장만 준다

```
이 이미지의 모양이 무엇처럼 보입니까? 사물 이름으로만 답해주세요.
떠오르는 첫 단어 3개를 순서대로 적어주세요.
설명하지 마세요. 맞히려 하지 마세요.
색이나 밝기가 아니라 형태가 무엇을 닮았는지만 답하세요.
```

세 문장이 각각 다른 실패를 막는다. 하나라도 빼면 데이터가 깨진다.

- **"사물 이름으로만"** — 없으면 축소·반전 이미지에 "아이콘", "역상", "야간모드" 같은 **메타 응답**이 온다. 리더가 형태가 아니라 *이미지 처리 상태*를 답하는 것이다. 실측에서 이 문장 없이 돌린 리더 3명이 전원 2·3장에서 무효 응답을 냈다.
- **"맞히려 하지 마세요"** — 퀴즈로 받으면 정답을 추론하려 들고, 첫인상이 아니라 추리 결과가 나온다.
- **"색이나 밝기가 아니라"** — 반전 판에서 특히 필요하다.

### 3. 리더 모으기

| 방식 | 인원 | 언제 |
|---|---|---|
| 서브에이전트 (맥락 없는 새 세션) | 5명 | **정제 단계마다.** 싸고 즉시 된다 |
| 사람 (친구·가족·카페 손님) | 5명 이상 | 최종 후보 확정 전. 이쪽이 진짜다 |

에이전트는 **사전 필터**지 사람의 대체가 아니다. 기계 비전은 사람 눈과 다르게 본다 — 에이전트가 통과시켜도 사람에게서 떨어질 수 있다. 반대로 에이전트 5명이 전부 같은 오독을 하면 그건 거의 확실히 실제 문제다.

에이전트를 쓸 때 지킬 것:

- **반드시 서로 독립된 세션.** 한 대화에서 다섯 번 물으면 첫 답이 나머지를 오염시킨다.
- **조건별로 리더를 나눈다.** 한 리더에게 3장을 몰아주면 두 번째부터 "같은 것"으로 처리해 답이 게을러진다. 기본 3명 · 축소 1명 · 반전 1명이 낫다.
- **모델급을 낮추지 마라.** 작은 모델일수록 메타 응답 비율이 높다.
- **이미지를 실제로 열었는지 확인한다.** 응답에 형태 묘사가 없으면 무효 처리. 못 열고도 그럴듯하게 답할 수 있다.

### 4. 집계

리더별로 이미지 3장 각각의 첫 단어 3개를 받는다. **첫 번째 단어에 가중치를 둔다** — 그게 첫인상이다.

| 판정 | 조건 | 조치 |
|---|---|---|
| 통과 | 의도한 개념(또는 같은 계열 단어)이 5명 중 **3명 이상**의 첫 단어에 등장 | 진행 |
| 주의 | 2명 | 형태를 조정하되 컨셉은 유지 |
| 재작업 | 1명 이하 | 컨셉은 살리되 **형태를 다시 그린다** |
| 치명 | 5명 중 4명 이상이 **같은 다른 것**으로 읽음 | 그건 이미 그 물건의 로고다. 형태를 버린다 |

"같은 계열"은 관대하게 본다 — 옹이를 노렸는데 "나이테", "나뭇결"이 나오면 통과로 친다. "눈", "새"는 다른 계열이다.

**축소(36px) 판에서 답이 급격히 갈리면** 그건 크기 대응 문제다. 형태가 아니라 획 굵기를 손본다.

**반전 판에서만 다르게 읽히면** 네거티브 스페이스가 형태를 만들고 있다는 뜻이다. 우리 사례가 정확히 이랬다 — 흰 로고에서 새 머리 느낌이 강해졌다.

### 5. 기록

결과를 케이스 폴더 `03-vector/blind-read.md`에 남긴다. 나중에 "왜 v4로 갔나"의 근거가 된다.

실측 예 (우디카페 v3, 리더 5명 중 4명 유효):

```
2026-09-02 · v3 · 심볼 단독
기본 첫단어 : 흐르는 / 물결 / 달 / 조개
계열        : 나선·소용돌이 4/4 · 물결·파도 3/4
의도(옹이·나이테·나무결) : 0/4
판정: 재작업 — 의도 0명. 단 만장일치 오독은 아님(나선 계열로 흩어짐)
조치: 나선은 유지, 나무를 지시하는 단서를 하나 넣는다.
      물결로 읽히는 원인 = 열린 호의 균일한 곡률 → 한 구간 곡률을 꺾는다
```

## 심볼 단독과 적용 상태는 따로 잰다

실측 사례: 심볼 단독 테스트에서 리더 4명 중 **"새"는 한 번도 나오지 않았다.** 그런데 같은 형태가 야간 간판 목업(반전 + 워드마크 + 어두운 배경)에서는 새 옆모습으로 강하게 읽혔다.

**맥락이 읽힘을 바꾼다.** 워드마크가 붙고, 배경이 깔리고, 크기가 정해지면 다른 것이 된다. 두 번 잰다.

| 시점 | 무엇을 | 왜 |
|---|---|---|
| 정제 단계 | 심볼 단독 | 형태 자체의 읽힘. 여기서 걸리면 형태를 고친다 |
| 적용 단계 | 목업 상태 그대로 | 실제로 사람이 만나는 조건. 여기서만 걸리면 배치·조합을 고친다 |

## 하지 말 것

- 결과가 마음에 안 든다고 리더를 더 뽑아 원하는 답이 나올 때까지 돌리기
- "이거 옹이 같지 않아?"라고 물어보기 — 유도질문은 데이터를 죽인다
- 통과 못 했는데 "설명하면 알아본다"고 넘어가기. **설명이 필요한 형태는 실패한 형태다**
- 사람 리더에게 답례로 의견을 유도하기. 첫 단어만 받고 대화를 끝낸다
